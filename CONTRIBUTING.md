# Как помочь архиву

Сайт — статический русский путеводитель по LonaRPG. Данные лежат отдельно от
компонентов, поэтому большинство правок не требует трогать React.

## Что можно исправить без кода

- факт: цена, вес, стат, координата, название, условие квеста;
- перевод или оригинальное название рядом с русским;
- пропущенный предмет, враг, достижение, локация;
- секрет или пасхалка с пометкой, обычная это игра или отладка.

Для правки нужен аккаунт GitHub. Проще всего открыть раздел **Сообщество** на
сайте: форма подставит страницу и версию сборки в GitHub Issue. Скриншот и
версия игры (`B.0.10.8.31` и т. п.) ускоряют проверку.

## Правила данных

1. **Источник важнее вики-пересказа.** Приоритет: файлы игры → наблюдаемое
   поведение в текущей сборке → официальная/английская вики → остальное.
2. **Не выдумывать координаты.** У служебных карт и вырезанного контента нет
   позиции на мировой карте. Такие записи идут в `src/data/debug-zones.ts` или
   в `secrets.ts`, но не в `locations.ts`.
3. **Не выдавать отладку за секрет.** Лаборатории, `debug:`-команды и тестовые
   карты помечаются как служебные, даже если в них есть интересный контент.
4. **Спорное — помечать.** Если данные расходятся между сборками, это пишется в
   тексте, а не прячется.
5. **18+.** Взрослый контент описывается сдержанно и по делу: механики,
   последствия, риски. Без пиратских сборок, персональных данных и обходных
   ссылок.

## Где что лежит

```
src/data/        предметы, снаряжение, квесты, локации, враги, достижения,
                 служебные карты (debug-zones.ts), секреты
src/sections/    страницы разделов
src/lib/         роутер, поиск, метаданные, аналитика, прогресс
scripts/         postbuild (выгрузки JSON, sitemap, HTML) и validate-dist
public/          статика, тайлы карты, service worker
```

## Локальная проверка

```bash
npm install
npm run typecheck   # типы
npm run build       # сборка + postbuild (dist/)
npm run validate    # проверка JSON, страниц и sitemap в dist/
npm run dev         # http://localhost:3000
```

`validate` запускается после `build`: он читает `dist/data/*.json`, проверяет
дубли id, границы координат, номера `MapInfos` у служебных карт, наличие HTML
для каждой страницы и записи в sitemap.

## Pull request

- одна тема на PR: данные, баг или фича;
- в описании — что изменилось и чем проверено (сборка, скриншот, файл игры);
- не коммитить `dist/`, `node_modules/` и локальные выгрузки;
- если меняется формат данных — обновить тип в `src/data/types.ts`,
  `scripts/build-data.ts` и проверку в `scripts/validate-dist.mjs`.

CI прогоняет `typecheck`, `build` и `validate` на каждый pull request и на push
в `main`. Красная проверка означает, что данные или сборка не сходятся.
